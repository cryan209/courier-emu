# x2 client measurement records

The pre-V.90 3453B 2.1.1 and later 3453C 2.3.33 execute the same rate-mask
intersection, position classification and variable-length record framing.
These are verified components of the client measurement-to-message path.
Analogue acquisition and automatic call-state scheduling are still unverified.
The variable-length message is distinct from the four-word Quad receiver
branch tested in [the server handoff](x2-rate-and-data-handoff.md).

## Rate selection

Original entries E773..E7A2 in 2.1.1 and 6818..6847 in 2.3.33 preserve header
control bits and choose the highest eligible bit of two 32-bit masks.

```
limit = data[037D] + data[0364] - 20
eligible = measurement_mask & host_mask & ((1 << limit) - 1)
selected = eligible.bit_length()
header = (initial_header & (0x7007 if role_bit_5 else 0x7003))
         | (selected << (3 if role_bit_5 else 2))
```

The result is also stored at 031C. The original continuation receives
`selected - data[0364] + 20` at 037D. The qualification is limits 1..31,
nonzero initial 037D and masks whose bit 31 is clear; zero intersections
are included. A zero initial 037D returns before mask intersection.
The physical interpretation of 0364 remains open. These indices are not
assigned nominal line rates merely from their numerical values.

| Firmware | Measurement low / high | Host high / low | Header | Role bit |
|---|---|---|---|---|
| 3453B 2.1.1 | D2A0 / D2A1 | F7C9 / F7CA | FCD0 | FFE9 bit 5 |
| 3453C 2.3.33 | 52A0 / 52A1 | 77C7 / 77C8 | 7CCE | 7FE9 bit 5 |

The comparison checks 496 contexts in each firmware: both role states,
eight offset values, all limits 1..31 and randomized sparse masks.

## Position classification and the variable-length body

F16B in 2.1.1 and 720A in 2.3.33 compare two six-position measurement
matrices. Each position occupies eight 16-bit words. The constructor groups
matching pairs of position blocks, assigns group numbers in first occurrence
order and emits one representative block per group. Tests cover one through
six groups, equal and different matrices, and randomized repeated groups.
The independent reconstruction matches the complete constructed body, not
just its length or checksum.

Let N be the number of distinct groups, and let D be one if the two whole
matrices differ and zero otherwise. The existing first five header words
are preserved. The following two control words are constructed:

```
word[5] = group[0] | group[1]<<4 | group[2]<<8 | group[3]<<12
word[6] = group[4] | group[5]<<4 | D<<8
body_word_count = 7 + 8*N*(1 + D)
```

The first matrix contributes N consecutive eight-word representative
blocks, in group order. If D is one, the second matrix contributes another
N blocks in the same order. The count ranges from 15 to 103 words. The
original constructor saves that count at CE9F or 4E9F respectively.
Its temporary 007D value is 8*N if D is one and zero otherwise; it is a
second-matrix block offset, not an independent sign count.

For six distinct positions, the two control words are 3210 and 0054,
or 3210 and 0154 when the matrices differ. For a repeated two-group sequence
0,1,0,1,0,1 they are 1010 and 0010, or 1010 and 0110.

In 2.3.33 the body starts at 7CCE, controls are 7CD3/7CD4, and bitmap data
starts at 7CD5. The corresponding 2.1.1 addresses are FCD0,
FCD5/FCD6 and FCD7. The final seven-word BLDD copies the assembled header
back to scratch; it does not replace the header with classification scratch.
The disassembler now displays source and destination in their correct order.

There are 76 whole-body comparisons per firmware, including twelve explicit
one-through-six-group/equal-versus-different contexts. The resulting 152
native-constructed buffers feed the original transmit initializers C5E8 and
4650. Those initializers install the source pointer, returned count, preamble
and serializer callbacks. The original serializers then execute with those
values. The harness enters the initializer; complete call-state selection
remains a separate boundary. The older initializer requires overlay 6 to
be restored after the overlapping overlay 7.

## Original framing and CRC

The 2.1.1 serializer starts at ADE2; the 2.3.33 serializer at 2E3A.
With source-selection flag 039F bit 14 set, they consume the body pointed
to by 033D and the word count at 03C9. They emit seventeen ones, a zero,
then each word least significant bit first followed by a zero separator,
and finally sixteen least significant bit first CRC bits. CRC starts at FFFF,
uses reflected polynomial 8408, excludes separators and has no final XOR.
The following callback emits a zero tail.

The earlier serializer independently matches this framing for 96 seeded
bodies of one, two, four, six, seven and nine words. Sixty-four four-word
bodies generated by the later serializer pass the original Quad bit receiver
and commit all four words unchanged. That establishes compatible framing;
it does not equate the variable-length client record with the Quad short body.

## Diagnostic report is a separate output

DE1D..DE6B in 2.1.1 and 5EC3..5F11 in 2.3.33 summarize six measurement
bitmap windows. They count windows with fewer than twenty set bits and pack
that count, local flags, a rate field and an auxiliary value into a report
at F7C0 or 77BE. Execution matches the packing formula for 1024 contexts.
The report pointer leads into the host diagnostic output path, including
OUT 0060; it is not the peer-negotiation body above. The six windows each
advance eight words before reading a high/low 32-bit bitmap pair.

This distinction removes 5EC3 as a candidate for the missing peer producer.
The actual rate/header writer and position constructor have separate entries.

## DSP condition timing and reproduction

The bitmap threshold exposed an emulator error: XC must sample its conditions
one full cycle before execution. A single-cycle predecessor cannot change
that sample. TI SPRU056D sections 4.5.6 and XC page 6-278 state this rule.
The native core now retains the correct accumulator/status sample, including
across delayed-branch slots. Six focused regression cases pass. The full
repository suite and a 64000/64000 symmetric call also pass after this change.

Run `.venv/bin/python tools/trace_x2_client_record.py`. Evidence is
`artifacts/x2-client-record-20261004/packer-verification.json`, with original
2.1.1 overlay listings in the same directory. The symmetric-call regression
is in `artifacts/x2-xc-pair-20261004`.

Remaining work is the analogue sample/measurement producer, interpretation
of the five header words, automatic scheduling of the variable-length exchange,
its peer receiver branch, frame alignment, and analogue payload decoding.

## Courier 403 additive count audit

The captured Courier 403 counterpart clarifies the arithmetic of 0364 without
establishing that its later record exchange runs in the observed call.
EA82..EABC returns N-0364+20; E970..E97B makes the same conversion from the
header to 0351; E11C consumes 0351+0364 bits. At 0364=5 the intermediate
count is N+15 and the total is N+20. The original consumer passes 216 bit-count
contexts. Assigning the additive count specifically to independent signs,
and binding the XMF header fields to the complete receiver, remain open.
See [Courier MP fields](x2-courier-mp-fields.md) for the profile, live-call
coverage and distinction between the short MP and the unexecuted later body.
